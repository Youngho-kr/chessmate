# 핵심 구현

## Stockfish 연동 분석
Stockfish를 실행 후 표준 입출력으로 UCI 명령어를 주고받습니다. 
FEN을 전달하면 최선의 수와 평가치를 반환합니다.

### 평가치 정규화
Stockfish의 반환 값 `score cp`는 항상 현재 수를 두는 플레이어 기준으로 반환됩니다. 
매 수마다 플레이어가 바뀌므로 이를 백 기준으로 정규화해서 처리합니다.

### 수 분류
정규화된 평가치의 변화량(delta)을 기준으로 각 수를 분류합니다. 
백이라면 delta 값이 양수일수록 좋은 수이고, 흑이라면 음수일수록 좋은 수입니다.

| 분류               | 기준      |
|------------------|---------|
| 최선 (Best)        | 0 이상    |
| 좋음 (Good)        | -20 이상  |
| 부정확 (INACUURACY) | -50 이상  |
| 실수(MISTAKE)      | -100 이상 |
| 블런더(BLUNDER)     | -100 미만 |

## 실시간 대전

### 게임 상태 관리

진행 중인 게임 상태를 Redis에 JSON으로 직렬화해 저장합니다. 
체스 게임은 매 수마다 게임 상태가 갱신되고 타이머가 존재합니다.
빠른 읽기/쓰기가 중요하므로 MySQL 대신 Redis에 게임 상태를 저장합니다. 
게임 종료 후에는 기보 및 결과를 MySQL에 영구 저장합니다.

### 타이머
`@Scheduled`로 1초마다 활성 게임의 타이머를 감소시킵니다. 
현재 차례인 플레이어의 남은 시간을 줄이고, 남은 시간이 0이 되면 자동으로 게임을 종료합니다. 
시간 제한이 없는 대전은 타임아웃 처리에서 제외합니다.

<br>

## 초대 코드 매칭

방장이 초대 코드 생성을 요청하면 서버에서 6자리 숫자 코드를 발급하고 Redis에 저장합니다. 
친구가 코드를 입력하면 게임 상태를 생성하고, 방장에게 WebSocket으로 매칭 완료를 알립니다. 
방이 생성되면 Redis에서 숫자 코드를 삭제합니다.

<br>

## 비로그인 게스트 세션

게스트 ID는 서버에서 UUID를 발급해 Redis에 저장합니다.
클라이언트가 직접 ID를 생성하면 조작이 가능하므로 서버에서 ID를 발급해 클라이언트에 전달합니다.

WebSocket 연결 시 로그인 사용자는 JWT, 게스트는 GuestId 헤더로 인증합니다.
